# Wokwi simulation of the keypad and panel

Work in progress. What is here and what is left, so the next session can pick
it up.

## Done

- `chips/ssd1680.chip.c` -- a Wokwi custom chip for the SSD1680: SPI command
  and data decoding, RAM with address counters (0x11, 0x44/0x45, 0x4E/0x4F),
  BUSY timing (attributes `fullUpdateMs`, `partialUpdateMs`), hardware reset,
  deep sleep. Draws the black/white RAM landscape, 296 x 152. Warns on the
  console about commands sent while BUSY or during deep sleep, and RAM writes
  outside the window. **Builds** with `make -C chips` (clang wasm32 +
  wasi-libc + libclang-rt-18-dev-wasm32); not yet run in Wokwi.
- `firmware/` -- an ESP-IDF app that links `firmware/main/keypad.c` and
  `epd.c` unmodified and prints `key <n> <name>` / `up <n>` per keypress.
  Built with `HP42S_WOKWI`, which moves the panel's CS and DC to GPIO 40 and
  42 (`board.h`), since the DevKitC-1 does not bring out 33 and 34. **Not yet
  compiled.**

- `diagram.json` and `keypad.test.yaml` -- generated by `gen_diagram.py` from
  `s_map` in `keypad.c`, the pins in `board.h` and the legends in `sim_main.c`,
  so they cannot drift from the code. Re-run it after any of those change.
- `wokwi.toml` -- points wokwi-cli at the IDF build and the chip.

**2026-09-27: all 37 keys pass.** Each press prints the right key number and
legend, each release prints `up`, and the SSD1680 chip sees a clean full
update at start then one partial per key, with no command sent while BUSY.

## Running it

The IDF build cannot run inside `/mnt/project-files`, so copy the sources out:

    mkdir -p /tmp/sim && (cd /mnt/project-files/hp42s && tar cf - firmware/main sim) | tar xf - -C /tmp/sim
    cd /tmp/sim/sim/wokwi
    make -C chips                      # needs wasi-libc, libclang-rt-18-dev-wasm32
    (cd firmware && idf.py set-target esp32s3 build)
    wokwi-cli --timeout 240000 --scenario keypad.test.yaml .

`WOKWI_CLI_TOKEN` must be set. A full run takes about two minutes of
simulated panel refreshes. Set the chip's `debug` attribute to `"1"` in
`diagram.json` to log every SSD1680 command.

`wokwi-cli --screenshot-part` does not work on a custom chip ("Part does not
have a valid framebuffer"), so the panel image is only visible in the VS Code
extension or on wokwi.com.
